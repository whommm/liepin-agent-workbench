# 猎聘寻访 Agent 工作台

面向猎头的桌面端寻访辅助工具。基于 PySide6 + Playwright + LLM，帮助猎头高效完成候选人寻访、匹配评估和证据整理。

## 核心功能

| 模块 | 说明 |
|------|------|
| **项目池** | 批量粘贴多个岗位JD，拖拽排序，程序按队列自动逐个处理 |
| **AI 寻访基准** | 根据JD自动生成"匹配词与岗位要求"草案，人工确认后执行 |
| **结构化岗位画像** | 将要求拆分为必须/偏好/否决/待确认条件，并维护替代条件、搜索词、证据规则和人才原型 |
| **自动搜索** | Agent 在猎聘自动执行多轮搜索、结果观察、策略复盘 |
| **搜索覆盖控制** | 按人才原型管理搜索组合，记录新增率、重复率和有效产出，动态分配探索预算 |
| **详情抓取** | 自动抓取候选人简历详情，区分直接证据、合理推断、未知信息和明确冲突 |
| **逐条件证据** | 先提取可定位简历事实，再逐条判断满足、部分满足、不满足或未知 |
| **不确定性感知排序** | 分开展示已知适配、潜在上界和证据覆盖，未知条件进入高潜待确认而不是直接降为不推荐 |
| **反馈与校准** | 记录人工判断、业务结果和两两排序偏好，用真实标签校准候选人排序 |
| **证据导出** | Excel 总览 + 候选人 Word 档案，含匹配证据、缺口、风险 |
| **批量打招呼** | 选中候选人后一键批量发送打招呼（使用自定义话术或平台默认） |

## 安装与启动

### 环境要求
- Python >= 3.10
- Windows（推荐）
- 已安装 Edge 或 Chrome 浏览器

### 方式一：虚拟环境（推荐）

```powershell
# 1. 创建虚拟环境并安装依赖
.\创建虚拟环境.bat

# 2. 启动程序
.venv\Scripts\python -m liepin_agent.main
```

### 方式二：手动安装

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e .[dev]
playwright install chromium
.venv\Scripts\python -m liepin_agent.main
```

### 打包为 EXE

```powershell
.\打包为exe.bat
```

打包后输出 `dist\猎聘寻访Agent工作台\猎聘寻访Agent工作台.exe`，约 110MB，双击即可运行。

## 首次使用配置

1. 点击右上角 **"设置"**
2. 填入你的 API 信息：
   - API Base URL（如 `https://opencode.ai/zen/go/v1`）
   - API Key
   - 模型名称（如 `deepseek-v4-flash`）
3. 浏览器通道选择 `msedge` 或 `chrome`
4. 点击 **"保存"**

> 配置保存在本地 `config.json`，不会上传到任何服务器。

## 使用流程

### 单个岗位寻访

1. 点击 **"新建"** → 粘贴 JD → 创建任务
2. 等待 AI 生成"匹配词与岗位要求"草案（约 10-30 秒）
3. 在右侧检查并修改关键词和岗位要求
   - 检查每条结构化条件的类型、权重、替代背景和证据要求
   - 检查直接对口、相邻可迁移等人才原型
4. 点击 **"确认并开始"**
5. Agent 自动执行搜索、抓详情、匹配、复盘，多轮循环
6. 达到目标有效候选池或最大轮次后自动停止
7. 点击 **"导出"** 生成 Excel + Word 档案

运行过程中可以在“搜索覆盖”页查看每个人才方向的探索状态、重复率和有效产出，
也可以暂停方向或调整优先级。候选人池支持“推荐 / 待确认 / 不合适”人工判断、
业务结果回填和两人相对排序，所有反馈都会保留当时的模型与岗位画像版本。

### 项目池批量处理（推荐多岗位场景）

1. 点击 **"添加到池"** → 粘贴 JD → 重复添加多个项目
2. 在项目池列表中 **拖拽** 调整处理顺序
3. 点击 **"开始队列"**
4. 程序自动处理第一个项目：
   - 生成寻访基准草案
   - 🔴 **弹窗提醒**（窗口置顶 + 任务栏闪烁）："基准已生成，请确认"
   - 你点击"去确认" → 右侧修改匹配词 → 点击"确认并开始"
   - Agent 自动跑完该岗位
5. 达到最大轮次后 **自动切换到下一个项目**，循环步骤 4
6. 全部完成后弹窗提示"所有项目已处理完毕"

**队列控制：**
- **"停止队列"**：暂停自动推进（当前运行中的任务不会终止）
- **"清理"**：一键移除已完成/失败的项目

## 任务状态说明

| 状态 | 说明 |
|------|------|
| 待确认基准 | AI 已生成草案，等待人工确认匹配词与岗位要求 |
| 已确认，待开始 | 基准已确认，可点击继续 |
| 运行中 | Agent 正在执行搜索、抓详情或匹配 |
| 等待人工确认 | 单步/监督模式下等待继续 |
| 已暂停 | 用户暂停或程序重启后自动恢复为暂停 |
| 已完成 | 达到停止条件（目标有效候选池、最大轮次等） |

## 导出内容

- **Excel 总览**：推荐总览、优先沟通/高潜待确认/可迁移探索/信息不足/明确不匹配分组、全字段明细
- **Word 档案**：每位候选人的独立档案，含匹配证据、缺口、风险、待确认问题

## 设计边界

本项目定位为**寻访辅助和证据整理工具**，不做自动雇佣决策：

1. 不自动淘汰候选人
2. 不自动联系候选人；打招呼只能由人工手动触发
3. 不把分数作为最终判断
4. 匹配结果以逐条件证据、缺口、风险和五态建议为核心

## 数据与隐私

- 所有数据保存在本地 SQLite 数据库（`liepin_agent_workbench.db`）
- 配置文件（`config.json`、`.env`）不会被提交到 Git
- 浏览器 Profile 保存在本地，登录态持久化
- LLM 调用仅传输岗位信息和候选人简历文本，不含用户身份信息

## 常见问题

**Q: 首次启动很慢？**  
A: EXE 首次运行需要解压依赖到临时目录，约 30-60 秒，后续正常。

**Q: 猎聘登录过期了？**  
A: 点击"打开猎聘"，在弹出的浏览器中重新扫码登录即可。

**Q: 可以同时运行多个任务吗？**  
A: 可以创建多个任务，但浏览器操作是串行的，实际执行会排队。项目池就是用来顺序调度的。

**Q: 程序崩溃后数据会丢失吗？**  
A: 不会。所有数据实时写入 SQLite，重启后会自动恢复上次中断的任务状态。

## 离线质量评测

人工标注积累后，可生成搜索与排序质量报告：

```powershell
uv run python scripts/evaluate_quality.py --db liepin_agent_workbench.db
```

报告按任务输出已标注样本上的精确率、召回率、假阳性、假阴性、校准指标、
搜索覆盖和候选人排序。使用 `--output report.json` 可保存 JSON 报告。
